# Avalonia platform interfaces

This matrix describes the API 26 backend for Avalonia 12.1.6. The default host embeds one XComponent.
The optional windowed host adds a stage-owned Avalonia window and native owned windows.

| Avalonia interface | Implementation | Scope |
| --- | --- | --- |
| `IRenderTimer` | HarmonyOS NativeVSync drives the shared Avalonia render loop when available. | The managed timer drives rendering when the native clock is missing, fails to request a frame or stops delivering frames. [NativeVSync API](https://developer.huawei.com/consumer/en/doc/harmonyos-references-V14/_native_vsync-V14/) |
| `IDispatcherImpl` | Avalonia's `ManagedDispatcherImpl` provides the UI dispatcher on the host's dedicated thread. | Native and ArkTS callbacks marshal work to this dispatcher. ArkUI work stays on the ArkUI thread. |
| `IPlatformGraphics` | Optional Skia EGL for the embedded view, windowed stage and owned windows. | PC Counter presented on both the native stage and child surfaces. A managed probe verified that a route-specific failure preserves the affected Window and falls back to software. [Rendering integration](integration.md#skia-egl-rendering) |
| `IPlatformSettings` | Provides system light/dark mode and the system emphasis color. | The PC Counter read the current emphasis color through Avalonia. SDK gesture-recognizer thresholds describe different operations from Avalonia's platform metrics, so the backend keeps Avalonia's interaction defaults. |
| `ICursorFactory` | Standard cursor styles and custom bitmap cursors with a pixel hotspot, applied per HarmonyOS window. | Styles use the closest available system shape. Custom images and hidden cursors depend on native input support. |
| `IPlatformIconLoader` | Loads Avalonia window icon data from a file, stream or bitmap. | HAP resources still supply the app icon. The window adapter has no dynamic title-bar icon setter. |
| `INativeControlHostImpl` | Embeds ArkUI NDK controls through `NativeControlHost` and `OpenHarmonyNativeControlHandle`. | PC Counter exercised real clicks, rectangular clipping and hit testing, visibility, disposal, and recreation. ArkUI controls occupy the layer above the Avalonia surface. [Native ArkUI controls](native-controls.md) |
| `IPlatformHandle` | A native HarmonyOS WindowManager ID is available when the corresponding window is known. | The `OH_WindowManager window ID` descriptor identifies an integer ID for WindowManager APIs. The XComponent surface token and graphics pointer have separate lifetimes. |
| `IPlatformDragSource` | Opt-in mouse and touch drag from Avalonia controls for text, HTML and web links. | PC Counter's Avalonia buttons delivered data to an independent app with a compact payload preview. Inbound READ and WRITE grants had the expected effects. Outbound file offers return `None` because an explicit READ policy still allowed the independent PC receiver to open a test file for writing. [Drag integration](drag-and-drop.md) and [system drag source](text-drag-source.md) |
| `IActivatableLifetime` | Application foreground and background events with `ActivationKind.Background`. | Window focus and application activation are tracked independently. `TryEnterBackground` and `TryLeaveBackground` return false because UIAbility's background request is asynchronous and foreground restoration is restricted for the Stage host. [UIAbilityContext](https://developer.huawei.com/consumer/en/doc/harmonyos-references/js-apis-inner-application-uiabilitycontext/) |
| `IScreenImpl` | Enumerates native displays with bounds, scale, orientation, primary display and working area. | PC Counter reported its real display and work area. Multi-display routing was exercised with injected snapshots. Bounds substitute for unavailable work areas. A non-primary display whose position is unavailable is omitted. [Display Manager API](https://developer.huawei.com/consumer/en/doc/harmonyos-references/capi-oh-display-manager-h/) |
| `IWindowImpl` | Freeform stage operations, extended title bar, native owned and nested windows, and independent auxiliary windows within the stage. | PC Counter verified position, title, topmost ordering, native decorations, a custom resize grip, nested modal completion, and independent window scaling, maximize, minimize and restore. The API supplies no dynamic per-window bitmap icon or Dock task visibility. Auxiliary windows share the stage task. [Owned windows](owned-windows.md) |
| `ITrayIconImpl` | Opt-in `TrayIcon` through Huawei's Desktop Extension Kit. | PC Counter exercised OS status-bar registration, left click, icon and hover-tip updates, hide, and re-show. The system provides one item per app and checks device support. [Status-bar integration](status-bar.md) |
| `INativeMenuExporter` | Exports `TrayIcon.Menu`, including bitmap icons, to the native status-bar context menu. | PC Counter displayed a menu item image and ran its Avalonia command from the native menu. The API supports root groups, a flat submenu and up to 20 entries at each level. It has no window-menu, disabled-item, shortcut or menu-opening fields. `NativeMenuBar` draws a window menu within Avalonia. [Status-bar integration](status-bar.md) |
| `ITopLevelImpl` | Avalonia overlay popup and opaque XComponent presentation. | ArkUI popup APIs accept native builders. Window alpha APIs affect different layers, device states and permissions, so the shared route retains the Avalonia overlay and reports opaque composition. [Rendering and popups](owned-windows.md#popup-and-transparency) |
| `ITextInputMethodImpl` | Native text input, selection, preedit, and Select All, Cut, Copy and Paste editor actions. | The PC editor attached and accepted keyboard input. A Windows native-ABI probe tested editing commands, privacy guards and preedit in a real TextBox. System paste needs authorization. Native TextConfig has no suggestion, capitalization, casing or locale preference setters. Private commands require a protocol agreed with the IME. [IME notes](ime-preedit.md) |
| `IClipboard` | HarmonyOS Pasteboard for text, HTML, bitmaps and application formats. | PC Counter verified a two-item rich round trip through the security PasteButton and an empty read after clear. File URIs need independently verified temporary grants. [Clipboard integration](clipboard.md) |
| `IStorageProvider` | Native file and folder selection, MIME type filters and granted public-directory lookup. | PC Counter saved and reopened a 24-byte sample through the MIME picker. The device provided a save type index and modification time. The SDK exposes the open selection without a type index and requires separate directory grants for direct folder lookup. [Storage integration](storage.md) |
| `ILauncher` | Web and custom deep links, mailto requests, and file or folder URI handlers. | PC Counter handled an unregistered link as unavailable. The stock image reported no installed handler for the tested email URI. File and folder launch depends on an installed handler for the assigned system type. |
| Hardware input | Mouse, finger touch, stylus tip and hover, keyboard, wheel and touchpad scroll. | PC Counter received mouse, touch and F13. The managed probe verified pen pressure, tilt and modifiers. The emulator's stylus injection emits ordinary touch, so physical pen and hover require compatible hardware. [Hardware input](hardware-input.md) |

See the [platform verification matrix](platform-validation.md) for the devices and probes used to validate these interfaces.
